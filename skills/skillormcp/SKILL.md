# skillormcp（判定 Skill / MCP 落点 + 审计错位，建议型 / Advisory）

## 定位声明（防漂移）

> **一句话脊柱**：MCP 是 Agent 使用的自定义 SDK 的**能力面**（连接、凭证、权限、审计封在服务端，硬），技能是这份 SDK 的**使用说明书**（调用顺序、状态机、确认门，软），凭证只留服务端、谁都不给。

- **ADVISORY 的准确含义**：本 skill "只报不改"指**不移动/不修改任何文件、不替人做决定**，不是说判定方法本身是软约束。技能天然是软的（会被漏读、误读、被注入绕过），真正不可逆的操作必须由 MCP 在协议层硬拦截——见「双层护栏」。
- **是什么**：一把"落点尺"——给定一项能力（或一段描述），判它的**能力归属**（该进 `skills/` / `mcps/` / 本地库 / 知识库 / 内联 / 密钥管理）与**部署形态**（常驻 MCP / 人工代理旁路 / 短时效凭证一次性 / 复用平台原生能力）；并对仓库里已存在的 skill 做**错位审计**（是不是在干 MCP 的活：持证、连内网、有状态连接、暴露万能 tool、对外写操作），以及对 mcp 做反方向审计（万能 tool、凭证作 tool 参数）。
- **不是什么**：不是强制机制、不是 CI 门禁；也**不判断"该能力是否适合外发 / 是否内部定制"**——那是人为审核范畴，AI 无法替你做这个分类。本 skill 只负责"落点"，不做发布范围裁决。它只产出建议 + 证据 + 起步脚手架，不移动、不修改任何文件；是否落地由人定夺。
- **为什么需要它**：当仓库同时存在 `skills/` 与 `mcps/` 两个目录（或打算这样组织）时，没有一把尺，后人容易把"连内网/持证/对外写"的活塞进 skill，造成能力错位——本 skill 就是这把尺，只管落点，发布范围由人审。

## 什么时候用

- 想新增一项能力，不确定做成 skill 还是 MCP。
- Review / 提交前，想核对某个 skill 是不是"能力错位"，或某个 mcp 是否命中反模式。
- 需要一段"该放哪 + 为什么 + README 草稿文案"，或落点确定后的起步脚手架（skill / MCP 二选一）。
- 拿不准"现有 SDK / 原始 HTTP API 能不能直接给 Agent 用"，或"一年只用两次要不要起常驻 MCP"。

## 核心判定轴：缺口类型

> 用"缺口类型"而非"AI 能力"做轴——模型会变强，缺口不会消失，规则才抗老化。

### 心智模型：MCP = Agent 用的自定义 SDK

传统 SDK 由平台方提供给开发者，在代码里显式 `import`；MCP 由服务方部署，Agent 在运行时连接、按 tool 名调用。一套 SDK 卖两样东西，落到 Agent 场景分成两层：

| 传统 SDK 里的东西 | Agent 侧对应物 | 归谁 |
| --- | --- | --- |
| 函数签名 / 类型 | MCP tool + tool schema | MCP（机器级契约） |
| env / 凭证文件注入的凭证 | 服务端持有，Agent 只传业务参数 | MCP（凭证不进上下文） |
| 连接池 / token 刷新 / 长连接 | 有状态常驻连接 | MCP |
| 权限校验 / 限流 / 审计中间件 | 写 tool 拆出 + 审批 / 权限 / 审计 | MCP（硬拦截） |
| README / 示例 / 注意事项 | 调用顺序、状态机、写前确认 | 技能（软指引） |
| 多语言 binding | 标准协议，多客户端复用 | MCP |

所以 **能力面归 MCP、用法面归技能**，两者合起来才是一套 Agent 能正确用好的 SDK。顾问输出要显式回答"这份 SDK 的说明书在哪"，避免做出只有 tool、没有方法的 MCP。

直接把原始 HTTP API 或普通 SDK 丢给 Agent 不行：前者让凭证进上下文、沙箱连不通内网、护栏只剩"请遵守"；后者假定调用方是版本固定的确定性程序，而 Agent 是运行时动态发现工具，会漏读、误读、被注入——硬护栏必须落在服务端。这也是反模式「把 MCP 当普通 SDK 直接搬」的根因。

> **类比不成立的 3 处**（别把比喻当规范）：① SDK 显式引入、版本固定，MCP tool 运行时发现，schema 一变就可能破坏调用，需要独立契约回归；② 传统 SDK 的凭证常在调用方环境，MCP 把凭证收到服务端，这是安全模型的本质差别；③ SDK 通常一语言一个包，MCP 是跨语言协议层、面向多客户端。

### 第一步：是否命中 MCP 六门槛（能力与强制）

命中任一 → **能力归属**应进 `mcps/`（同时通常还需一个 skill 规定方法）；但"归属"不等于"必须自建常驻服务"，先分清门槛性质，再定部署形态：

| 门槛性质 | 包含 | 处置 |
| --- | --- | --- |
| 硬缺口（红线，无逃生舱） | 1 凭证不可见、3 执行位置受限、4 必须硬拦截 | 与频率无关：凭证与连接永远不交给 Agent，护栏不能只写在技能里。是否值得起常驻服务，另按第三步的成本维度定形态 |
| 软缺口（可谈形态） | 2 有状态/常驻、5 多客户端复用、6 机器级契约 | 与频率 × 维护成本 × 复用客户端数一起权衡 |

| # | 门槛 | 一句话判断 |
| --- | --- | --- |
| 1 | 凭证不可见 | 凭证能让 Agent 看到吗？（含沙箱、环境变量）不能 → MCP，凭证只在服务端 |
| 2 | 有状态/常驻连接 | 需要会话、token 刷新、长连接、订阅推送？ |
| 3 | 执行位置受限 | 目标系统只有特定网络/机器能访问？（内网、跳板） |
| 4 | 必须硬拦截 | 写操作、生产环境的护栏能只靠"建议"吗？不能 → MCP 层权限/审批/审计 |
| 5 | 多客户端复用 | 多个 Agent/客户端要接入同一能力？ |
| 6 | 机器级契约 | 调用需要类型校验、结构化输入输出？ |

### 第二步：是否命中技能六门槛（方法与软约束）

命中任一 → 应进 `skills/`（+ 技能内脚本）。

| # | 门槛 | 一句话判断 |
| --- | --- | --- |
| 1 | 不可逆/对外写 | 做错了能回退吗？不能 → 技能（写确认门） |
| 2 | 凭证/敏感 | 会碰客户或生产密码？→ 技能管安全边界（只写"怎么用"，不写字面凭证） |
| 3 | 隐性方法 | 换个 Agent 会做错或漏做？ |
| 4 | 确定性逻辑 | 每次重写会不一致？（解析/对账/分页去重） |
| 5 | 团队一致性 | 多人多 Agent 要同一行为？ |
| 6 | 可发现性 | 不写下来就没人知道存在？ |

### 第三步：全不命中 / 命中但低频 —— 频率、成本与分层

**优先级三条**：

1. **硬缺口优先于软缺口**：命中 1 / 3 / 4 时能力归属先定在服务端侧，与频率无关；但**是否值得自建常驻 MCP**另按成本维度算，别把"必须能做"误答成"必须常驻"。
2. **只中技能门槛、不碰外部系统**：技能独立成立，按频率决定做成技能还是本地库，无需 MCP。
3. **命中凭证但偶发**：先过成本维度（见下），不要无脑起常驻服务。

**成本维度（逃生舱）**：判定输出是两段，不是单值。能力归属上凭证与连接必须在 Agent 上下文之外（红线不变）；部署形态由 `频率 × 维护成本 × 复用客户端数` 决定：

| 形态 | 适用 | 代价 / 约束 |
| --- | --- | --- |
| 常驻 MCP | 高频、多客户端复用、需要硬拦截与审计 | 要维护服务、连接、权限、审计 |
| 人工代理旁路 | 偶发、只读、无状态 | 人在旁路用已授权凭证执行，Agent 只拼语句与解读结果 |
| 短时效凭证一次性 | 偶发且密钥系统能签发临时凭证 | 跑完即焚、不起常驻服务；仍需凭证不进对话 |
| 复用平台原生能力 | 平台已提供同等连接 | 优先降级，别重复造 |

一句话：**命中硬缺口解决"必须能做"，是否"值得做成常驻服务"让频率与维护成本说话。** 一次性任务若方法已被已有技能 / 知识库覆盖，内联时直接调用即可，不必新建；只有当方法本身不存在且不可逆风险低时，才允许纯对话内联。

**两条取数原则**：

- 技能内脚本 vs 共享库：只服务某一个技能的确定性步骤放技能目录内；被多个技能 / 团队复用且不含业务口径的通用能力下沉为共享库。
- 本地脚本 vs MCP：无状态、无凭证、沙箱内可跑的纯计算用本地脚本；一旦涉及凭证、会话、内网，不要再用本地脚本硬扛。

**六层分层表**（把东西放进对的层，比写得多详细更重要）：

| 层 | 放什么 | 判断标准 |
| --- | --- | --- |
| 知识库 | 客观事实 / 方法论 | 跨版本稳定、可检索 |
| 技能 | 方法 / 契约 / 确认门（SDK 的说明书，软） | 换人做会做错、漏、越界 |
| MCP | 有凭证 / 有状态 / 跨网络的能力 + 硬护栏（SDK 的能力包） | 命中 MCP 六条门槛 |
| 本地库 / 脚本 | 无状态、无凭证的确定性计算 | 沙箱内可跑、多次复用 |
| 对话内联 | 一次性 / 动态操作 | 低频、可逆、结果容忍差异 |
| 密钥管理 | 凭证 / 密码 | 只在 MCP 服务端或配置中，不进对话、不进技能 |

分层原则：知识归知识、方法归技能、连接与强制归 MCP、纯计算归本地库、凭证归密钥、一次性归对话。两条最常见的错层：把客观事实清单塞进技能正文（应进知识库）、把无凭证的通用能力各自包成技能（应下沉本地库）。

> **凭证红线（分级）**：无论落点，凭证不进对话、不进技能正文、不作为 tool 参数；由密钥管理注入 MCP 服务端或 gitignored 配置。**提及/引用**凭证（说明怎么用、`os.environ`/`${...}` 引用、从 `_secret`/`secrets.` 安全源读取）是合规的，**字面凭证值**才是红线，**凭证作为 tool 参数**属于错位。低频逃生舱只改变部署形态，不放宽这条红线。
> **「引用」的判定边界（扫描器校准）**：配置里写 `credential_refs: {key: SERVICE_API_TOKEN}`（引用名指向环境变量）属于引用、不是凭证值，扫描器不得判红线。判据：值是**全大写且含下划线**的环境变量名形态（`SERVICE_API_TOKEN` / `API_KEY`），或被 `<...>` 包裹的占位符，或 `${...}` / `os.environ` 形式。**已知边界**：含下划线的全大写口令（如 `PASSWORD_X`）会被当作引用放行，需人工复核——宁可放过一个可疑值，也不要把每个正常配置项都报成红线（误报会让扫描报告失去可信度）。

> **门槛 4/5/6（写操作 / 多客户端 / 结构化契约）**：扫描器可自动检出"写操作"信号（requests.post/DELETE、httpx.post、kubectl apply/delete、rm -rf、DROP TABLE、TRUNCATE、terraform apply、git push、docker rm、以及 `subprocess.run(["terraform","apply"])` 这类 argv 列表写法等）；"多客户端复用""机器级契约"为软判断，扫描器不自动判定，需人工确认。

## 双层护栏：为什么只在技能里写"请先确认"不够

技能是写给 Agent 的指引，可能被漏读、误读或被注入绕过；MCP 的护栏落在协议层，即使 Agent 没读到也越不过去。不可逆 / 对外可见的写操作必须两层都有：

| 层 | 机制 | 性质 | 作用 |
| --- | --- | --- | --- |
| 技能 | 写确认门、流程状态机 | 软 | 让 Agent 知道该停下来问人 |
| MCP | 写 tool 单独拆出，设审批 / 权限 / 审计 | 硬 | Agent 漏读、误读或被注入时仍能拦住 |

所以"只在技能里写一句请先确认"是危险的：它依赖 Agent 读到了、读懂了、且没被注入要求绕过。顾问输出命中不可逆写时，要同时检查技能确认门与 MCP 写 tool 的硬拦截，缺一即标为护栏不完整。

## 两种用法

### 模式 A：顾问（给定能力描述）

输入一段能力描述，输出：
1. 建议落点（`skills/` / `mcps/` / 本地库 / 内联 / 知识库 / 密钥管理）+ **部署形态**（命中凭证 / 连通性但低频时必填：常驻 MCP / 人工代理旁路 / 短时效凭证一次性 / 复用平台原生能力）；
2. 命中了哪条门槛（引用上面的表）与门槛性质（硬缺口 / 软缺口）；
3. 一段可直接贴进 README 的草稿文案（功能说明 + 触发词）；
4. 起步脚手架指针：
   - 落点=`skills/` → 复制 `templates/skill/SKILL.md`（frontmatter 三段式骨架）+ `templates/skill/README_INDEX_SNIPPET.md`（双 README 索引条目），替换 `<...>` 占位符即可。
   - 落点=`mcps/` → 复制 `templates/mcp/`（README.md / server.py / config.example.yaml / requirements.txt / .gitignore），替换 `<mcp-name>` 等占位符即可起步。
5. **SDK 自检 + 双层护栏**：MCP 是否只承担能力面（凭证 / 连接 / 权限 / 审计藏在服务端）、技能是否承担用法面（顺序 / 状态机 / 确认门）；不把凭证塞进 tool 参数、不把方法写进 tool description；命中不可逆写时，是否同时有技能确认门（软）与 MCP 写 tool 的审批 / 权限 / 审计（硬）。

**示例（输入 → 输出要点）**：
> 输入："我想做一个能连公司内网 K8s、用跳板机 ssh 进去跑 kubectl 排障的能力。"
> 输出：落点 `mcps/`（命中 门槛1 凭证不可见、门槛3 执行位置受限、门槛4 必须硬拦截，均为硬缺口）+ 部署形态「常驻 MCP」（排障高频、多客户端复用）；SDK 自检：能力面（跳板连接 / 凭证 / 审计）留服务端，用法面（排障顺序、写操作确认门）另配技能，二者缺一即护栏不完整；附 README 草稿与 `templates/mcp/` 指针。

> 另一示例（落点=skills/）："我想做一个清理代码注释、只描述现状的 skill。"
> 输出：落点 `skills/`（命中 技能门槛3 隐性方法、门槛5 团队一致性），不碰外部系统，无需部署形态；SDK 自检：本能力纯属用法面，不必配 MCP；附 README 草稿；并提示参考 `templates/skill/` 骨架。

> 低频反例："一年只用两次，连内网库查一个数，要不要起常驻 MCP？"
> 输出：能力归属仍落在服务端侧（命中 门槛1 凭证不可见、门槛3 执行位置受限，硬缺口无逃生舱）；但部署形态按成本维度判为**人工代理旁路 / 短时效凭证一次性**，明确不起常驻服务，并复述凭证不进对话、不进技能、不作 tool 参数的红线。换成 SDK 说法：这份"内网查询 SDK"的能力面不能交给 Agent，但不必为一年两次的调用常驻部署。

### 模式 B：审计（给定 skill/mcp 目录或全仓）

调用 `scripts/audit_placement.py <目录或 skills/>`，扫描 `SKILL.md` 与 `scripts/` 等文本文件（含 `.env`/`.toml`/`.ini`/`.cfg`/`.conf`）：
- 匹配"MCP 形"信号：
  - **凭证**：字面凭证值（password=/secret=/api_key=/AKIA/sk-/私钥头/Bearer/JWT/连接串内嵌 `user:pass@host`/`Authorization: Basic`（兼容 `"Authorization":` 字典形式与 curl 裸形式）等，红线；右侧需为引号值、非引用、非类型标注、非安全源调用）vs 提及/引用（说明怎么用、`os.environ`/`${...}`/`_secret`/类型标注，提示，合规）；**遮罩仅在判定为字面值行上进行**，非字面值行（如 `token = _issue_token(...)`）不误遮。
  - **内网/连通性**：ssh/kubectl/完整四段私有 IP/跳板主机/vpn/专线（红线；版本号如 `10.15.2`/`3.10.4.5` 不误报）；
  - **有状态/常驻**：token 刷新/长连接/订阅/websocket（红线）；
  - **万能 tool**：execute_sql/run_shell/os.system/eval（不含 `model.eval()` 方法调用），红线；
  - **写操作**：requests.post/DELETE、httpx.post、kubectl apply/delete、rm -rf、DROP TABLE、TRUNCATE、terraform apply、git push、docker rm，以及 `subprocess.run(["terraform","apply"])` 这类 argv 列表写法（列表先拼接为字符串再匹配），红线。
- 对 **Python 的 mcp 目录**（识别到 FastMCP/mcp.run/@mcp.tool/@server.tool/server.tool）额外做**反方向审计**：暴露万能 tool、凭证作 tool 参数（内联 keyword 形式 `password=db_pass` 也检）。**tool 函数参数名分两级**（无视类型标注）：**强**（password/secret/api_key/private_key/access_token/client_secret/bearer/credential 等，几乎确定是凭证）→ 红线 **MCP反模式**；**弱**（裸 `token`、`credentials`，可能是分页/会话 token 等合法用途）→ 降级为 **提示** **MCP可疑参数**，结论中请人工确认；**白名单**（`page_token`/`next_token`/`cursor`/`csrf_token`）明确不报。优先用 **AST 解析 `@*.tool` 装饰函数**的参数名；**若文件语法错误 AST 失败，回退正则粗扫并明确提示"该文件无法 AST 解析，已回退正则（可能漏检跨行签名），请人工复核"**——绝不静默通过（退出码不再为 0）。**非 Python（TypeScript/JavaScript 等）源文件不做反向参数审计**（AST 仅支持 Python；团队只用 Python，忽略其它语言），普通规则（写操作/内网/万能 tool）仍生效；但报告会在「人工确认项」明确给出提示"非 Python 的 MCP 文件, 反向参数审计未执行, 请人工复核"，不会与"未发现红线"混同。命中反模式/写操作/万能 tool 时给出 **MCP 设计人工确认清单（逐条）**：① 一个 API 一个 tool（避免万能 tool）？② 方法是否写进 tool description（应留给 skill）？③ 是否纯计算也做成了 MCP（本可做成 skill）？④ 写 tool 是否带限时一次性审批令牌 + 审计日志？⑤ SDK 类比自检：能力面（凭证 / 连接 / 权限 / 审计）是否只在服务端，用法面（顺序 / 状态机 / 确认门）是否留给技能？⑥ 读写语义是否进 tool annotations（只读 readOnlyHint / 写 false / 不可逆 destructiveHint，未标注按写侧处理）？tool 是否薄委托（校验 + 护栏 + 1-3 行委托，超过 15 个拆 client.py + 映射表）？
- 对 **SKILL.md** 含写操作/有状态/万能 tool 信号但全文无"真正确认步骤"短语（如"执行前需经用户确认"）时，提示补充确认门（不可逆操作需人工确认）；仅出现裸"确认"字样不构成确认门。
- 报告对**字面凭证值脱敏**（只显 `key=***`，引号内整串含空格口令、连接串密码、`Authorization` 字典/裸形式均遮），不回显密钥原文。
- 输出发现清单（file:line + 严重度 + 类别 + 脱敏后信号），并给结论：
  - 命中"凭证字面值"(红线) → **必须移除硬编码凭证，改用密钥管理（环境变量/密钥库注入）**，这不是"下沉 MCP"能解决的；
  - 命中其它红线 → **疑似能力错位/反模式，建议下沉 `mcps/` 或拆分写操作护栏**；
  - 含内网/私有地址 → **仅作事实信号提示，由人确认该内容是否适合放在公开仓库**（本 skill 不做此项裁决）。

## 诚实口径 / 不自欺不变量

- **只报不改**：绝不自动移动/修改文件；处置权留给人。
- **行号可追溯**：摘录逐字引用原文，输出前回查行号与原文对得上，不要凭记忆报行号。
- **置信封顶**：未做实证的判定置信最高「中」；治理/红线类（凭证外发、对外写）命中即可高置信告警。
- **发布范围不裁决**：本 skill 不判断"能力是否内部/定制/应外发"——那是人为审核，AI 无法替你分类。扫描器命中内网/私有地址时只作事实信号提示，结论交由人确认。
- **自身包豁免，非全局跳过**：扫描器只豁免其自身包路径（自审干净），被审计 skill 自带的 `templates/` 同样会被扫描；不要将"自审干净"误当成"全局不审计"。
- **判定边界（做成之后怎么守）**：本 skill 只回答"要不要做 / 放哪"，不覆盖做成之后的另一块工程问题——MCP 服务端自身的信任边界（"凭证只在服务端持有"隐含信任该服务端；租户隔离、审计留痕、服务端加固需另行设计）。技能与 MCP 之间的契约回归**已提供**：`scripts/contract_check.py`（快照见骨架硬约定⑦），tool schema 变更必须过基线 diff；但"该不该接受某次破坏"仍是人按 major 版本纪律裁决，脚本只负责拦下并报告。
- **软硬区分**：技能是写给 Agent 的指引，可能被漏读、误读或被注入绕过；不可逆操作必须双层护栏（技能确认门 + MCP 硬拦截）。只在技能里写一句"请先确认"不算护栏。
- **成本维度不是放宽红线**：低频逃生舱只改变部署形态，不改变凭证不进对话 / 技能 / tool 参数与硬拦截要求。
- **定期复核按缺口类型**：用"缺哪类东西"而非"AI 现在能不能"复核；被模型覆盖的一致性 / 接入型技能、被平台原生能力替代的自建 MCP，都要做降级评估。
- **统一配置，函数经入参传变量**：MCP 侧所有配置由一处收口（`Settings` 之类）并校验必填项，内部函数把配置当入参接收；**配置不得成为 tool 参数**——tool 签名就是给 Agent 看的 schema，配置一旦成为参数就会进上下文，等于把内部结构交给模型改。连接参数写配置，不写死在 tool 代码里。
- **MCP 骨架七个硬约定**（`templates/mcp/server.py` 已实现，改骨架前先对照）：① 双传输按 `MCP_TRANSPORT` 环境变量切换（stdio 本地单租户 / http 远程多租户绑内网地址，启动校验拒绝 `0.0.0.0`/`::` 通配与公网 IP）；② 凭证收口在服务端（每个引用独立 env 回退链、只在同引用内回退，支持成对凭证与 static/oauth2 获取模式，凭证只进请求头，401 刷新后重试一次，链用尽报错不跨引用借用）；③ HTTP 唯一出口 `request_api`（统一超时与 verify_tls 默认开，禁止 tool 里另起 HTTP 客户端；`transport` 参数是测试注入点——有外部依赖时用假传输对象做无网络回归，不 mock httpx 本身）；④ 写护栏 `write_policy` 二选一（gate 按写类别的 env 开关、缺失即拒，写类别是服务端常量不接受 Agent 指定 / token 两步令牌），写拒绝与令牌失效一律 `PermissionError`；⑤ `@audited` 定义即应用（敏感值哈希脱敏、三条路径留痕），列表输出走 `paginate()` 截断分页；⑥ **读写语义进 tool annotations**——只读 tool 标 `readOnlyHint: true`、写 tool 标 `readOnlyHint: false`（不可逆再开 `destructiveHint: true`），语义进协议层、不进参数不进描述，未标注的 tool 契约回归按写侧处理（保守）；⑦ **tool 薄委托 + 契约回归**——tool 函数体只做边界校验+护栏+1–3 行委托 `request_api`，HTTP/整形/分页归骨架 client 函数，tool 超过 15 个必须拆 `client.py` + `TOOL_REGISTRY` 映射表并配脚本校验；契约快照用 `scripts/contract_check.py` 经**实际传输**（stdio/http 二选一，不许 import 服务端模块静态内省）出 tools/list 快照（名/schema/是否写/破坏性/版本）与基线 diff——删 tool、删必填、类型或枚举收窄、读写标注翻转判**破坏**（须阻断提交或升 major + `--allow-breaking` 显式放行），新增/放宽放行。
- **凭证要能续期**：OIDC 授权服务器签发的 client_credentials access_token 通常是短命的（有效期由 IdP 侧配置，常见几分钟），骨架若把 token 当静态环境变量读，MCP 跑一会儿就会整体 401。凭证应在服务端用 client secret 自动换取并缓存续期（client secret 同样只走环境变量）。
- **自检**：`scripts/audit_placement.py --self-test` 用内置正向/反向 AST/脱敏/后缀/反例/绕过口/argv 列表/字典 Authorization/确认门断言；改匹配规则后必须先过 self-test（含解析失败回退、参数名强弱分级与白名单、环境变量名/占位符不得误判红线）。
