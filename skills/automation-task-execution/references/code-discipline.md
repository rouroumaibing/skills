# 代码纪律与质量门

> 本文件给出代码交付的编码纪律与质量门执行细则：规则是语言无关的 prompt 纪律，配合「按被测代码位置分治 + 确定性工具 + 三级降级」框架落地。
>
> 何时读：Phase 3 写码或重构前；Phase 4 执行九对账的「质量门对账」时；轻量档交付前。

## 1. 分治的第一性原理：质量门评什么

静态检查扫的是**文件**，动态检查评的是**测试套件**——crapper 的覆盖率与 mutator 的幸存者都不读测试文件，它们**经由被测代码给测试打分**（覆盖率 = 测试触及生产代码的面；幸存变异体 = 测试的盲区）。所以分治轴不是「产出物是生产代码还是测试代码」，而是**被测代码在不在本地**。三个原生工具扫树时跳过 `test`、`spec` 目录且显式指定路径也不豁免（已实测确认）——这只砍掉了「扫测试文件」这一条信号最差的通道（测试天然共享 AAA 骨架，静态查重多为意图性结构相似），不影响动态通道。

| 场景 | 生产代码侧（脚本 / CLI / 被改的业务代码） | 测试套件侧（自动化用例） |
|---|---|---|
| 被测代码在本地（同仓单元 / 组件测试） | crapper 复杂度·CRAP + dryer 查重（mutator 对长期维护项目可选） | **mutator 幸存者 = 机械质量门**，crapper 覆盖率佐证；辅以随包文本脚本（断言强度 / 写死值） |
| 被测代码在外部系统（接口自动化，本 skill 主场景） | 本地如有脚本产出，复杂度 / 查重照跑 | 动态通道不可用 → 机械门 = 随包文本脚本（它们不跳 test/ 目录）；**等价动态手段 = 契约变异冒烟**：在受控入口（mock / stub）故意改一处响应字段或状态码，确认测试会变红——抓不住契约变更的测试就是断言太弱；mock 不可用时在交付说明标注【契约变异冒烟未执行】；结构查重不做机械核对，靠 Phase 4 参数化 / 乱序规则 + 人工评审 |

配置 / 文档不设质量门，走既有对账项（写死值清零、门控改动标注）。六语言之外直接走 L2 / L3，不必尝试 L1。

## 2. 三级降级：普适性怎么保

| 级别 | 条件 | 动作 | 交付标注 |
|---|---|---|---|
| L1 原生工具 | 交付语言 ∈ crapper 支持的六语言（Clojure / Java / Go / TypeScript·JS / Rust / Python）且工具已检出 | 跑 `./crapper`（建议 `--threshold 30`，exit 2 即超阈）、`./dryer`；被测代码在本地时加 `./mutator`——它同时是测试套件的机械质量门（§1） | 最差项与快照位置（`.metrics/`）写进交付说明 |
| L2 语言等价物 | L1 不可用（语言不支持，或工具未检出且用户暂不安装） | 用交付语言生态的等价物：复杂度（gocyclo / eslint max-complexity / radon 等）、重复（jscpd 等）、变异（Stryker / PIT 等） | 标注【质量门 L2：等价物】 |
| L3 纯规则 | 连等价物也不可用（新语言 / 环境装不了任何工具） | §3 编码纪律作为纯约束执行，人工复核补位 | 标注【质量门 L3：未做机械核对】 |

**工具未检出时不静默跳过**：向用户提示安装命令（见 §4 工具卡）；用户选择不装则降 L2 / L3，并把实际走到的级别写入交付说明。这与「环境不可用 → 静态探索 +【未运行验证】」是同一降级模式——区别只在降的是质量门，不是探索。

## 3. 编码纪律（语言无关，逐条可判定）

写码与重构时逐条对照；违反任何一条即「质量门对账」未过。规则条款本身语言无关，只在 L3 或日常自检时单独生效，L1 / L2 下与机械核对互为补充——机器查得出复杂度，查不出「这个抽象根本不该存在」。

### 先让它跑

* 一处决策只住一个地方；交付解决问题的最小改动。
* 先定数据形状，再写逻辑；优先做能让后续每个阶段都变简单的事。
* 若并发写者会成为问题，就不要共享状态。
* 新需求不往旧设计上打补丁：先问「若它一开始就在，我会怎么设计」，想清楚后分片交付。
* 两个共享同一前提的修复在同一关卡失败时：把前提写成一句话，数出掌握失衡分配的角色，移除该分配；没完成这一步，不开始下一个修复。（Attack the Premise——专治连环修补。）
* 加任何东西之前，先做减法。
* 以可检验的终态为目标；计划内且可回退的中途破坏是允许的。
* 工作不显然时先造工具：手做一个单元，让工具复刻该单元。

### 架构

* 领域建模：把领域放进让非法状态不可表达的结构里；维护领域术语表；代码已清晰且局部时不折腾。
* 边界纪律：数据在入口处校验，内部信任；业务逻辑收进纯函数。
* 类型纪律：让非法值写不出来；外部数据在入口解析一次；不压制编译器。
* 幂等：任何操作跑两次、或中途崩溃后重跑，终态相同。
* 共享状态分离：不需要同一可变物的各方各持一份；确需共享时只允许一个写者，并用结构强制这一点。

### 再做对

* 修根因：先复现，再修因；只把崩溃藏起来的 guard 不是修复。
* 测试行为而非实现：测试按使用者的方式调用代码，检查使用者能看到的结果；若把每个函数都改成返回空值后测试仍通过，扔掉重写。（与铁律 4 断言强度守恒同源。）写不出诚实断言的用例宁缺毋滥——不造假断言换绿灯，转待确认项问人。
* 重构三步：钉住行为 → 改结构 → 证明行为未变。

### TDD 消歧（与主流程的边界）

* 「先写失败测试再改代码」适用于**被修改的业务 / 生产代码**（轻量档交付、修复类改动）：先红后绿，最小改动通过。
* **不适用于** Phase 1 探索期（禁止写任何自动化代码——先见真实响应再定契约）与 Phase 3–4 的用例生成（按主流程：探索 → 冒烟 → 批量）。
* 一句话：改业务代码先红后绿，生成用例先探后写。

## 4. 工具卡（可选增强器）

三个工具均**只报告不改文件**，输出快照供人工复核；均为外部仓库，本 skill 不打包、不自动安装。首次运行会自动创建 `.venv` 并安装依赖（Python 3.8+）。

| 工具 | 作用 | 阈值与退出码 | 运行 | 未检出时向用户提示的安装命令 |
|---|---|---|---|---|
| crapper | 每函数圈复杂度 + 覆盖率 + CRAP 分数，快照写 `.metrics/crap.edn` | `--threshold 30`（工具风险分级：1–5 低，5–30 值得看，30+ 复杂且缺测试；严格纪律取 10）；exit 2 = 最差分超阈 | 目标仓库根执行 `./crapper` | `git clone https://github.com/unclebob/crapper.git`，检出后 `./crapper` |
| dryer | 结构性重复检测（Jaccard 结构指纹，名字与字面量归一化后比对） | 默认 0.82，`--threshold` 可调；exit 0 = 仅报告 | `./dryer` | `git clone https://github.com/unclebob/dryer.git`，检出后 `./dryer` |
| mutator | 变异测试：暴露测试杀不死的变异体，幸存者即测试盲区 | exit 0 = 全杀灭；exit 3 = 有幸存者 | `./mutator`（**要求 crapper 检出在相邻目录** `../crapper`，命名空间与函数名从其快照取；**只扫描自身检出目录内的文件**，对交付仓库使用时把两工具 clone 进目标仓库内） | `git clone https://github.com/unclebob/crapper.git` 与 `git clone https://github.com/unclebob/mutator.git`（两目录相邻检出） |

* 六语言之外（C/C++、Kotlin、Swift、PHP、Ruby、Shell 等）直接走 L2 / L3，不必尝试 L1。
* mutator 成本高（全量变异 ≈ 测试跑 N 倍）：长期维护项目启用；一次性交付建议只跑 crapper / dryer。
* 工具报告是线索不是结论：可能漏报（未覆盖的写法）或误报（合理重构），每条都要人工复核——与 `check_assertion_strength.py` 同一立场。

## 5. 执行习惯

* 行为日志：Phase 4 批量实现期的关键动作与理由随手记进交付说明，交付时随「产出物清单」汇报——**不另立日志文件**，并入既有产出物。
* 上下文窗口：批量实现期的大批量机械操作（逐用例复制模式、全仓检索）交给子代理，主对话只保留汇总与决策——与「探索落文件」互补：文件是记忆，子代理是手脚。
* 提交纪律：小步、有序、可回退；每条 commit 写清 why / what / how proved。推送节奏遵循项目既有约定，本 skill 不强制推送主线。
* worktree 清理：清理前确认没有在用依赖；未提交的工作先问决策再动。
