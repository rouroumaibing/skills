## 2. 维度检查清单（补漏用）

推演抓不到不挂在具体步骤上的东西（清理策略、授权边界、完成定义），用这张表扫一遍：

| 维度 | 检查问题 | 典型谁填 |
|---|---|---|
| 目标与完成定义 | 做到什么算完成？覆盖哪些用例？ | B |
| 期望值来源 | 断言以文档 / 需求 / 现状为准？谁说了算？ | B |
| 环境与访问 | 地址、网络、依赖的上下游服务？ | A 或 B |
| 账号与权限 | 测试账号、角色、凭证放在哪？ | B |
| 测试数据 | 是否存在、归谁、可否重复、怎么清理？ | B（状态本身是 C） |
| 调用顺序与状态依赖 | 哪个操作必须先做？用例间是否共享状态？ | C |
| 副作用与授权边界 | 哪些环境和数据允许动？ | B |
| 执行方式 | 命令、参数、工具版本？ | A |
| 已知坑与不稳定点 | 历史上出过什么问题？（有上下文文件先查它） | B，有记录则 A |
| 非功能约束 | 超时、并发、幂等、限流？ | C |
| 交付约束 | 目录结构、代码风格、是否接 CI？ | B |

## 3. 缺口表（分流结果）

| # | 缺口 | 维度 | 类型 | 影响 | 处理 | 状态 |
|---|---|---|---|---|---|---|
| 1 | <描述> | <维度> | <A/B/C/D> | <阻塞/降级/可忽略> | <见下方分流规则> | <待处理/已解决> |

分流规则：

- **A** → AI 直接自查（读代码 / 文档 / 跑命令），不必问人；进表只为留痕。
- **B** → **阻塞的 B 类，解决前不得动手；非阻塞的 B 类，可先做不依赖它的部分，同时等回复**；全部汇入 §4 一轮集中提问，每题的「阻塞：是/否」就是判定依据，不用另加字段。
- **C** → 改写成探针：「假设 <X>，探针：<真实调用 / 对比动作>」，排进 Phase 1。
- **D** → 写入 §6「已采用的默认假设」，**不算待确认项，不阻塞**，交付时汇总给人事后确认。
