# 求职辅助全流程 (jd-hunting)

辅助用户完成从简历分析到面试准备的全链路求职工作。每一步产出落盘为 Markdown 文件，便于编辑与复用。

## 触发场景

- 用户想要找工作 / 求职 / 投递简历
- 用户提供简历或工作经历，希望分析适合岗位
- 用户想按地点、政府优秀企业名单筛选公司并检索岗位
- 用户需要针对具体岗位定制简历或准备面试问答

## 前置依赖

- **浏览器**：`TRAE-browseruse-external`（用户本机 Chrome，复用登录态）
- **简历解析**：`pdf`、`docx` skill（第一步解析 PDF/Word 简历）
- **检索**：`WebSearch`、`WebFetch`、`Task`（子代理调度）
- **操作系统**：同时适配 macOS 与 Windows。`TRAE-browseruse-external` 通过 CDP 连接本机 Chrome，平台差异（Chrome 路径、快捷键、调试端口）由该 skill 屏蔽；jd-hunting 本身不写死任何平台特定路径或快捷键。
- **CDP 连接约定**：本机 Chrome 须以远程调试端口启动（统一 `--remote-debugging-port=9222`），`prompts.md` 与子代理一律通过该端口连接，不写死系统路径或 UserDataDir；连接失败即回报"Chrome 未以调试端口启动"，交用户重启 Chrome。
- **用户前提**：执行前需在本机 Chrome 登录目标招聘网站（不限操作系统），并确保 Chrome 已以 `--remote-debugging-port=9222` 启动。

## 前置输入

- 用户的简历文件（PDF/Word/纯文本/Markdown）或工作经历自述（学历、项目、职责、技能，越详细越好）
- 目标办公地点（例如「某某市某某路」，用于地图范围筛选）
- 期望薪资范围（可选）
- 可接受的通勤半径（默认以开车半小时路程为准）
- 是否接受远程岗位（默认否；接受时远程岗位不受地点过滤约束）
- 求职状态（在职-看机会 / 离职-随时到岗，默认在职-看机会）
- 所在省市（用于第四步定位政府优秀企业名单）

## 招聘网站登录规则

完整清单见项目根 `jb-web.md`（可选）；核心站点见下表，脱离本项目亦可用。核心规律：

- **浏览岗位**：绝大多数网站无需登录即可查看岗位标题、薪资等基础信息。
- **投递简历 / 查看联系方式 / 深度浏览**：基本都需要登录。
- **国家官方平台**（中国公共招聘网、中国国家人才网、24365、国聘网等）浏览门槛最低，信息权威。
- **企业官方招聘站**可浏览，投递需登录。

> 网站登录由用户自己完成。在用户已登录的浏览器会话中，通过 `Task` 调用 `TRAE-browseruse-external` 子代理控制浏览器检索岗位，不替用户输入账号密码。

## 工作流程

### 第一步：收集简历与工作经历

- 读取用户提供的简历文件或自述文本。**若输入为 PDF 文件，先调用 `pdf` skill 提取文本；Word 调 `docx` skill；纯文本/Markdown 直接读取。** 提取后再进画像分析。
- 提取关键字段：学历、工作年限、技术栈、项目经历、职责、成果、证书。
- 若信息不全，主动追问补充，尤其学历与年限。
- 画像须按固定 Schema 结构化输出，确保后续步骤数据基准一致：

```json
{
  "核心技能标签": ["Go", "Kubernetes"],
  "工作年限": 5,
  "学历": "本科/非全日制",
  "期望城市": "杭州",
  "期望薪资": "20-30k·14薪",
  "求职状态": "在职-看机会",
  "允许远程/跨城市": false,
  "项目履历摘要": [{"项目": "", "角色": "", "成果": ""}]
}
```

- **缺省容错**：所有字段允许 `null`。若 `期望薪资` 或 `期望城市` 为空，向用户发起一次交互询问补全；用户未答则取简历最近一段工作的地点/薪资作默认推论值，并在画像中标注 `来源: 推论`。`求职状态` 缺失默认 `在职-看机会`。
- 产出 `01-profile.md`：结构化的个人画像。

### 第二步：初步分析适合岗位

- 基于画像分析，给出 **5 个建议岗位**，每个附理由（匹配的能力点、行业、发展空间）。
- 岗位名称需贴近市场通用叫法，便于后续检索。
- 推荐前用 WebSearch 校验每个岗位名在主流招聘网站是否真实存在且为热门叫法，避免推荐市场没有的岗位名。
- 产出 `02-recommended-roles.md`。
- **Checkpoint**：必须等用户确认/调整岗位列表后再进入第三步，不自动续跑。

### 第三步：招聘网站检索岗位

- 按第二步推荐的岗位名称，在各招聘网站查找 **以执行当日为基准往前 3 个月** 内发布的岗位（执行时填入今日日期）。
- 识别岗位名称相近的招聘信息（如「Go 开发」「Golang 工程师」「后端开发(Go)」视为同一类）。
- **时间过滤软化**：超过 3 个月的丢弃；发布时间不明但其他条件匹配的，单列"待核实"区，不直接丢弃。
- 按用户指定的办公地点过滤；若用户接受远程，远程岗位不受地点约束。
- **数量上限**：每个网站每个岗位名抓取前 30 条。
- **执行方式**：通过 `Task` 调用 `TRAE-browseruse-external` 子代理（套用 `prompts.md` 模板 A），在用户已登录的 Chrome 中检索。对每个网站单独发起一次子代理任务，可并行多个独立网站。
- **登录态检测下沉**：不由主流程预检（占上下文 + 首页不显登录态）；模板 A step 1 直接访问搜索结果页 URL，重定向后 URL 含 `login`/`passport`/`sso` 或出现登录弹窗即 Fast-Fail 返回。
- **Fast-Fail 退场**（替代"中途挂起等待"）：子代理遇验证码/滑块且无法自主绕过时，保存已抓数据并立即返回，回报 `状态：触发验证码 | 已抓取：N 条 | 建议：手动通过后重跑或转 WebSearch`。由主流程决定是否提示用户介入或切兜底。
- **站点黑名单**：主流程收到某站 Fast-Fail（未登录/连续失败）后，将其加入本次运行黑名单，后置步骤不再重试该站，转 WebSearch 兜底或跳过。
- 产出 `03-jobs-from-sites.md`：按网站分节汇总，含"待核实"区与"失败/黑名单站点"说明。

### 第四步：政府优秀企业名单筛选

- 按政府官网公布的优秀企业名单检索公司：
  - 专精特新中小企业
  - 专精特新「小巨人」企业
  - 高新技术企业
  - 独角兽企业
  - 瞪羚企业
  - 科技型中小企业
- 名单来源：工信部、各省/市经信委、科技局官网公示。**取最近一年公示版**，过期名单不纳入。
- 按用户前置输入的所在省市定位名单，不全国撒网。
- 对名单中的公司，找到其 **官网招聘页**，检索是否有匹配岗位。通过 `Task` 调用 `TRAE-browseruse-external` 子代理（套用 `prompts.md` 模板 B）执行。
- 产出 `04-gov-list-companies.md`。

### 第五步：地图范围筛选公司

- 以用户指定地点（如「某某市某某路」）为圆心，**优先开车半小时路程**范围内查找公司名单。
- **优先用地图网页版"驾车路线/测距"按实际通勤时间筛选（半小时内）；地图无此能力时退化为半径 15 km 近似，并在产出标注"近似半径，实际通勤以面试邀约时确认为准"。**
- **执行工具链**（按优先级，无密钥则跳过该档）：
  1. WebSearch 搜「`所在市` 产业园区 入驻企业」「`所在区` 科技园 企业名录」获取结构化名单
  2. `TRAE-browseruse-external` 打开高德/百度地图网页版，按地点 + 关键词查 POI
  3. 不调用需密钥的地图 API（无密钥场景）
- 范围内公司不足时，逐步扩大半径（15→25→40 km）。
- 对范围内的公司，在招聘网站、官网招聘页检索是否有匹配岗位。
- 产出 `05-nearby-companies.md`。

### 第六步：岗位信息汇总与适配度评估

对第三、四、五步收集到的候选岗位，先 **去重** 再评估：

- **去重键**：公司全称（归一化去「有限公司/股份有限公司」等后缀差异）+ 岗位名归一化（去除括号、空格、级别词）。
- 跨站点重复岗位合并为一条，保留信息最完整的来源，其余来源记入"同岗多平台"备注。

对去重后的每个岗位，整理：

| 字段 | 说明 |
| :--- | :--- |
| 公司名称 | 全称 |
| 岗位名称 | 招聘网站原标题 |
| 岗位描述 | 职责与要求 |
| 工作地点 | 详细地址 |
| 薪资范围 | 最低–最高 |
| 适配度评分 | 四维度合计 0–12 分（见下表），9+ 高 / 5–8 中 / <5 低 |
| 胜任要点 | 该岗位需具备的能力点，用户已具备/欠缺 |
| 面试经验 | 全网检索该公司/岗位的面试经验分享（牛客、看准、脉脉、知乎等）；需登录平台拿不到时标注"需登录查看" |
| 公司背景 | 存续/融资/社保人数/司法风险/失信（仅高适配度查，来源企查查·天眼查·裁判文书网；通过 `prompts.md` 模板 C，输入含 JD 宣称公司全称 + JD 摘要） |
| 薪资对标 | 该岗位市场均价（优先 `WebSearch` 检索公开行业薪资报告/同岗位交叉对比；看准网登录壁垒强，仅作补充），标注 JD 薪资"高于/持平/低于市场" |
| 投递链接 | 公司官网投递入口，若无则标注招聘网站投递入口；均无则标注"仅可现场/邮件投递" |
| 岗位有效性 | 点进详情页确认未下线；已下线标注"已关闭"剔除 |

**适配度打分表**（各 0–3 分，合计 0–12）：

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
| :--- | :--- | :--- | :--- | :--- |
| 技能匹配 | 完全不沾边 | 沾边 <30% | 匹配 30–70% | 匹配 >70% |
| 年限匹配 | 差距 >2 年 | 差距 1–2 年 | 差距 ≤1 年 | 完全符合 |
| 地点匹配 | 超出可接受半径 | 远程可接受 | 半径边缘 | 半径内 |
| 薪资匹配 | 低于期望 >30% | 低于 10–30% | 低于 <10% | 达到/超过期望 |

**学历与年限放宽规则**：
- 岗位要求「全日制本科」但工作年限要求低（如 1–3 年），若用户为非全日制但经验匹配，可纳入投递范围。
- 岗位年限要求高于用户实际年限 1 年以内，且其他条件高度匹配，可纳入。
- 适配度评估需说明放宽依据。

产出 `06-jobs-summary.md`，按适配度评分从高到低排序，保留 top 20。
- **Checkpoint**：用户确认汇总表与高适配岗位名单后，再进入第七步生成定制简历。

### 第七步：定制简历与面试问答

对每个高适配度（9+ 分）岗位：

1. **定制简历**：基于 **原始简历 + 岗位 JD** 做改写（画像仅用于匹配判断，不作改写源，避免丢失原始措辞与量化成果），突出匹配的项目经历与技能，弱化无关内容。产出 `07-resume-<公司名>-<岗位名>.md`。
2. **通用面试问答**：针对该岗位准备以下 6 题的答复草稿，产出 `07-interview-<公司名>-<岗位名>.md`：
   ```
   1. 请做个自我介绍
   2. 为什么想换工作？
   3. 为什么选择我们公司？
   4. 分享一次你在 xx 项目中遇到困难的经历？
   5. 你期望的薪资是多少？
   6. 你还有什么要问我的嘛？
   ```
   - 自我介绍：结合岗位 JD，1–2 分钟口述稿。
   - 为什么换工作：正向表达，避免抱怨。
   - 为什么选本公司：结合第六步查到的公司信息（业务、优秀企业资质等）。
   - 项目困难经历：从用户画像中挑一个最贴近岗位的项目，按 STAR 结构。
   - 期望薪资：参考第六步薪资范围 + 用户期望，给区间。
   - 反问环节：准备 2–3 个体现专业度的问题。

## 成功标准 (Definition of Done)

满足以下任一即视为本次流程完成：
- 用户对至少 3 个高适配度岗位确认收到完整交付物；或
- 用户主动终止。

单个高适配岗位完整交付物 = 定制简历 + 6 题面试问答 + 公司背景报告 + 投递链接。

## 执行约定

- 所有产出 Markdown 文件统一放在 `outputs/` 目录下（按上述文件名）。
- 浏览器自动化一律通过 `Task` 调用 `TRAE-browseruse-external` 子代理（用户本机 Chrome，CDP 9222），不在主对话直接操作。
- **子代理 prompt 一律套用 `prompts.md` 模板，填入变量后发起，禁止临场自由发挥。**
- **并发上限**：同时运行子代理 ≤ 3（本机 Chrome 标签上限），超出排队。
- **成本提示**：七步全跑 token 消耗大；第三步建议先跑 1–2 个高优先站点（BOSS直聘、智联）试水，确认流程再扩量。
- **跨平台**：产出文件路径交由 Write/Edit 工具处理（自动适配分隔符）；文案不出现 macOS 独占假设（不写「Cmd+T」，改用「新开标签页」）。
- 涉及多个独立网站的检索，并行发起子代理任务提升效率（受并发上限约束）。
- 任何需要账号密码的操作一律交还用户完成，skill 不代填凭据。
- 政府名单、地图 POI 检索优先用 `WebSearch` + `WebFetch`，必要时辅以 `TRAE-browseruse-external`。

### 断点续跑

- 每个 outputs 文件即为该步的完成标记。续跑时先 LS `outputs/`，按编号判断进度。
- 已存在的文件：默认询问用户「覆盖 / 跳过 / 续跑」；用户未明确则跳过该步。
- Checkpoint 点（必须等用户确认才前进）：第二步后（岗位列表）、第六步后（汇总表确认进入定制）。

### 隐私与安全

- `outputs/` 目录加入 `.gitignore`，避免简历泄露入库。
- 汇总表 `06-jobs-summary.md` 中公司电话/联系人脱敏（保留来源链接即可）。
- 定制简历稿 `07-resume-*` 保留用户完整联系方式（用于投递），但仅落盘本地不外传。

### 文件名清洗

- `<公司名>` 取前 10 个字符，去除括号、空格、斜杠、反斜杠、冒号等非法字符。
- `<岗位名>` 同样清洗，并用连字符替换空格。
- 示例：`07-resume-字节跳动-Go后端工程师.md`。

### 数量约束汇总

- 第三步：每网站每岗位名 ≤ 30 条。
- 第六步：汇总表保留 top 20（按适配度评分）。
- 第七步：仅对高适配度（9+ 分）岗位生成定制简历与面试问答。
