## 文件命名规则

| 步骤 | 文件名规则 | 说明 |
| :--- | :--- | :--- |
| 第一步 | 01-profile.md | 固定 |
| 第二步 | 02-recommended-roles.md | 固定 |
| 第三步 | 03-jobs-from-sites.md | 固定 |
| 第四步 | 04-gov-list-companies.md | 固定 |
| 第五步 | 05-nearby-companies.md | 固定 |
| 第六步 | 06-jobs-summary.md | 固定，补充检索并入此文件 |
| 第七步 | 07-resume-{公司}-{部门/JobID}-{岗位}.md | 有部门/JobID 时 |
| 第七步 | 07-resume-{公司}-{岗位}-{序号}.md | 无部门/JobID 时，序号递增 |
| 第七步 | 07-interview-{公司}-{部门/JobID}-{岗位}.md | 面试问答，同上规则 |

**补充检索并入主文件**：补充检索**并入主文件**（如 06-jobs-summary.md），不新建 06b/06c。主文件用 `## 补充检索（{日期}）` 分节。

**同公司同岗位多部门命名**：避免覆盖风险，追加部门/JobID 区分符。无部门时按生成顺序追加序号（1/2/3...），保证文件名绝对唯一性。

## 文件名清洗

- `<公司名>` 取前 10 个字符，去除括号、空格、斜杠、反斜杠、冒号等非法字符。
- `<岗位名>` 同样清洗，并用连字符替换空格。
- 示例：`07-resume-字节跳动-Go后端工程师.md`。

## 文件索引头规范

每个 outputs 文件开头 3 行 HTML 注释（渲染时隐藏，不污染阅读）：

```markdown
<!-- INDEX-HEAD
step: 第三步 | 产出: 03-jobs-from-sites.md | 状态: 完成
摘要: 4 站检索，BOSS 12 条 / 智联 8 条 / 猎聘 0 条(黑名单) / 前程 5 条
黑名单: 猎聘(未登录 Fast-Fail) | 待核实: 3 条(发布时间不明)
-->
```

## 主对话通知规范

每步完成后主对话必须输出：

```
✅ 第 {N} 步完成
📄 产出：{文件名}
📊 摘要：{一句话}
👉 产出位置：{绝对路径}
{若涉及 Checkpoint} 请查看后回复"继续"进入下一步
```

## Checkpoint 交互模板

涉及 Checkpoint 的步骤，主对话必须输出以下模板：

```
Checkpoint：第{N}步已完成
产出文件：{文件名}
汇总：{一句话摘要}

请确认（回复"确认"或列出调整项）：
```

**硬约束**：
- 用户未显式回复"确认"或列出调整项 → 不进入下一步
- 用户回复"继续"不等于确认 → 提示"请显式确认汇总表或列出调整项"
- **超时兜底**：Checkpoint 等待用户确认超过 5 分钟无响应，或用户连续 2 次仅回复"继续" → 自动接受当前有效岗位进入下一步，避免自动化/无人值守场景死锁
  - 自动接受时在 00-index.md 标注"Checkpoint 超时自动接受"
  - 自动接受不剔除"待核查"岗位，仅剔除"已关闭"岗位
