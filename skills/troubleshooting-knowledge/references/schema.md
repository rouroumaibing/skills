# 条目 schema（v1）与规则细则

SKILL.md 只保留流程骨架；本文是字段、类型与规则的单一权威来源。改本文不碰 `knowledge/`，改事实条目不碰本文。
**数值型规则（粒度上限）与扫描模式的最终取值以 `scripts/validate.py` 的常量为准**——本文只做说明，避免在四份文档里各抄一份导致漂移。
校验器：`scripts/validate.py`，只做校验、不生成索引文件；条目由消费方递归全量扫描（条目量小，且「索引+全扫合并」存在失效路径仍可命中的隐患）。

## frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | ✓ | schema 版本号，当前 `1`；validate 校验，未知版本拒绝 |
| `domain` | ✓ | 组件/系统域（`k8s`、`envoy-gateway`、`order-svc`、`postgres`） |
| `scope` | ✓ | `oss`（开源通用，可随 skill 分发）/ `personal`（个人项目，不出库）；必须与所在目录一致 |
| `components` | – | 涉及的组件名数组 |
| `symptoms` | – | 症状关键词（`崩溃重启`、`5xx 陡增`）；**检索入口，起草必写全**（口语与术语都写，见「检索可达性」） |
| `error_codes` | – | 错误码/状态码/事件 reason/响应标志，保留原始写法；**检索入口，起草必写全**；**数字型必须加引号**（`"503"`），否则 YAML 解析成 int 被拒 |
| `versions` | – | 限定版本数组（如 `[1.x]`）；省略 = 版本无关；数字开头同样加引号。**doc-sourced 条目必须带版本信息**（本字段非空，或 evidence.run 写明文档版本） |
| `envs` | – | 适用环境/区域/租户类别数组（如 `[prod, staging]`）；省略 = 环境无关 |
| `aliases` | – | 同义归并别名（缩写/中英文叫法/旧名）——转译/检索时用它对齐不同措辞；**检索入口，起草必写全，不留空**（validate 对空值发 warn） |
| `status` | ✓ | `active` / `deprecated` / `disputed`（缺省按 active 处理） |
| `confidence` | ✓ | `verified` / `observed-once` / `doc-sourced`，见下 |
| `evidence` | ✓ | **非空数组**，每项 `{ run, what, covers? }`——依据哪份上游文档（名+版本+章节）或哪类运行时观测方式、在哪观测到什么；**不写具体日期、访问日期、某次排查的时间戳**（见「不写具体时间」）；`covers` 可选字符串数组，标注本条证据覆盖的正文位置（如 `资源匹配关系 R1`）。**无证据不收**；条目里定义的每个 R# 都应在某条 `covers` 里有出处，否则 validate 告警 |
| `source` | ✓ | 来源描述（哪份上游文档及章节 / 哪类观测事实；**不写具体日期或「哪次排查」**）。证据强度看 `confidence` + `evidence` |
| `related` | – | 关联条目的相对路径数组（如 `oss/foo-bar.md`）：按链路/软件边界拆出的独立条目、同链路上下游条目在此串联。validate 校验：字符串数组；指向不存在 → warn；**oss 条目禁止指向 personal/**（error，与 superseded_by 同规——私有信息不出库）。两关联条目同 domain 含相同错误码时**豁免**「重复错误码」告警（同一链路拆成两条时错误码本就共享，不是重复）；其余同 domain 重复错误码仍告警 |
| `superseded_by` | – | 仅 `deprecated` 时填：替代条目的相对路径（validate 校验指向存在、目标 active、无循环引用）；**oss 条目禁止指向 personal/**（私有信息不出库） |

**条目形态只有一种**：所有条目都是链路/系统型通用排查参考，按模板全量结构写全；frontmatter **不含 `type` 字段**（出现即判 error）。具体某报错（如 503、CrashLoopBackOff）不单独建条目——错误码属于哪条链路/系统由消费方模型按语义自行判断（这类归类 AI 可直接识别），不需要在库里维护「错误码 → 条目」映射表；把报错线索写进对应条目的 `error_codes` / `symptoms` 与「异常归因速查」表，消费方命中条目后靠速查表定位环节即可。

## 不写具体时间

条目是长期可复用的链路/系统参考，不对应某一次排查。**整个条目不出现任何具体时间**：
正文、`frontmatter`、`evidence.run`、`source`、表格与图示里都不写某年某月某日、访问日期、
排查 run 的日期/ID、日志时间戳、「截至某日」等时效表述。理由：具体时间会把通用事实绑成
一次性个案记录，并随时间失效；来源定位用可复现的标识（文档名 + 版本 + 章节、运行时
观测方式/证据位），不靠日期指认。

**frontmatter 不含 `updated` 字段**：条目不体现具体时间，validate 不做过期复核；残留
`updated` 判 **error**（与 `type` 字段同规）。复核条目是否有新证据靠 diff 与 `evidence` 追加体现。
`assets/conflict-report-template.md` 要求运行时证据写「什么时间」是冲突报告的定位信息
（哪个 pod、哪行日志），不是知识条目，不在此限。

## 正文固定结构（从模板复制，不自由发挥）

按「先正常、后异常」组织，顺序固定（所有条目都按模板 `assets/entry-template.md` 的全量结构写）：

1. **是什么**——一句话定位 / 解决什么问题 / 谁在用从哪进来 / 边界（不负责什么）/ 形态与版本 / 术语。
2. **组件与架构**——mermaid 组件关系图 + 组件表（角色 / 职责 / 部署形态 / **如何找到**：命名、标签、命名空间）。
3. **正常链路（请求怎么走 / 正常行为）**——先写系统自身的客观链路，含四小节：
   - **资源匹配关系**（`R#` 编号表）：哪个资源与哪个资源通过哪个字段对上（写真实字段名、具体匹配规则）、对不上时的表现（状态条件写在它真正出现的资源上）；
   - **流量走向（或生命周期）**（`L#` 环节表）：流量/状态按什么顺序流经哪些环节、每一环的默认行为（超时/重试/同步异步）；
   - **控制面下发路径**（`P#`，可选）：声明式配置如何变成数据面配置——「改了没生效」类症状靠它定位；
   - **正常表现（健康基线）**：健康时各资源状态值、日志特征、关键指标形态。
   无请求链路概念的对象写成「正常行为」。
4. **逐环节排查（沿链路对照）**——按 `L#`/`P#` 逐个展开，**覆盖全部环节**；每环写「正常表现 / 异常表现 / 区分点 / 取证落点」；超出证据直接支持的内容用行内标记 〔推论〕 / 〔待复核〕 标注。
5. **异常归因速查**——表格：`| 现象/错误码 | 环节 | 归因类别（回指 R#） | 证据位 | 详细条目 |`；**「环节」列必填**，引用第 4 节的环节编号，每行对应到某一环；成因类别之间无排查先后依赖；「详细条目」列链接 related 里的关联条目，没有留空不编。
6. **状态、事件与日志语义**——本系统的 status 条件 / reason / 事件 / 日志标志位 / 指标的含义字典；只写语义，不写处置。
7. （可选）**配置语义**；（可选）**边界与置信度说明**——不适用整节删除。

### 锚点体系（R# / L# / P#）

- `R#` = 资源匹配关系编号（资源匹配关系表）；`L#` = 请求/生命周期环节编号；`P#` = 控制面下发环节编号。
- 约束：每个 L#/P# 环节应能回指其依赖的 R#；逐环节排查覆盖全部 L#/P#；速查表每行写环节。
- **锚点引用完整性由 validate 做 warn 级机械校验**（误报代价低）：表格首列 `^|\s*(R\d+|L\d+|P\d+)\s*\|` 收集已定义编号；L/P 已定义但逐环节未覆盖、正文引用未定义 R#、速查表「环节」列出现未定义编号都会告警（规避 mermaid 围栏噪音）。仍建议模板尾部自检双重保险——warn 不阻断，但锚点断裂会让消费方取错证据。

## 知识条目禁写注释

条目（`knowledge/**/*.md`）里出现 `<!--`（HTML 注释）或 frontmatter 里的 YAML `#` 注释，一律 **error**：消费方整篇读入条目，两种注释内容模型照样能看到，是绕过密钥/注入扫描的隐蔽注入通道。字段取值与写法说明放 `assets/entry-template-guide.md`，不进条目；模板 `assets/entry-template.md` 本身也保持零注释。判定口径：`#` 只有位于**行首或前面有空白**时才是 YAML 注释；`#` 前是非空白字符（如文档锚点 URL 的 `/spec/#gateway`）属合法值，不报 error。**块标量（`|`/`>`）内容整块跳过**：里面的 `#` 是数据（日志特征行常见），不是注释；块内容仍受全文扫描，不因跳注释判定而免检。

## confidence 定义

- `verified` = 该行为在至少一次运行时取证中被直接观测（日志/事件/状态原文），且 `evidence` 能指认观测点；**verified 条目不允许出现 〔推论〕/〔待复核〕 标记**（validate 告警）；
- `observed-once` = 仅单次观察、未复现或证据不完整；
- `doc-sourced` = 上游官方文档明确陈述的行为语义，未在本环境运行时复现（oss 条目常用）；**必须带版本信息**（versions 非空，或 evidence.run 写明文档版本与章节），否则 validate 告警。

未达 `doc-sourced` 的推测**不进库**（推测类结论由河道按证据分级标注，不落知识层）。检索排序优先级：`verified` > `observed-once` > `doc-sourced`。条目内混有多种强度时，弱者用行内标记区分，机器可统计。

## 事实/流程边界判据

只写「证据在哪、长什么样」（如 `describe pod` 的 `Last State` 里能看到退出码），不写有先后顺序的**排查命令串**。判定法：句子说的是「系统哪一环出了什么问题」→ 是事实；说的是「你先跑哪条命令」→ 是流程，删掉（流程归河道）。**链路/生命周期顺序本身是系统客观事实**（请求物理上就按此顺序流动、状态机本来就按此转移），按链路环节组织条目不违反本判据——判据约束的是排查动作的执行顺序，不是系统拓扑。

## 粒度：拆分看边界，不看体量

- **拆分标准 = 链路或软件边界不同**：两条独立链路（如 Ingress 与 GatewayAPI）分开写、用 `related` 串联；**同一个主题内容再多也写全、不拆**。把一条完整链路切成多条会破坏「正常链路 → 逐环节排查 → 异常归因」的连续性，消费方也拼不回请求模型。
- `SIZE_LIMITS` 单档软上限（数值以 `scripts/validate.py` 常量为准）**只用来提醒「这一条是不是混进了两个主题」**：超限 → **warn**，人工复核主题是否单一；**它不是拆分指令**——确属同一链路/软件边界，即使超限也照写全。
- **写全不拖累读取**：消费方按 `references/consumer-contract.md` 的字节预算取水，用 `scripts/read_entry.py --sections <节名>` 按节、`--hop L#` 按环节号切片，只读命中的部分。压读取成本靠切片机制，不靠拆条目。

## 检索可达性（起草必写全）

所有条目都是链路型通用排查参考，具体报错由消费方按错误码自行归类、不单独建条目，因此**条目的 frontmatter 就是检索主入口**：`scripts/search.py` 是纯关键词匹配（frontmatter 语义字段权重 3、正文权重 1；中文整词未命中才按 2-gram 回退）。用户口头说法没写进条目就命不中，因此起草时四项必须写全：

| 项 | 写什么 | 作用 |
|---|---|---|
| `symptoms` | 用户会说的现象，**口语与术语都写**（`Pod 一直 Pending`、`5xx 陡增`） | 命中自然语言查询 |
| `error_codes` | 错误码 / 状态码 / 事件 reason / 响应标志，保留原始写法 | 命中精确线索 |
| `aliases` | 缩写与中英文叫法、旧名 | 对齐不同措辞；配合无命中时 `search.py` 的 `hint=` 换别名重试 |
| 正文「异常归因速查」表 | 现象 → 环节号（`L#`/`P#`） | 命中条目后定位到具体环节，再用 `read_entry.py --hop` 切片取证 |

validate 对 `symptoms` / `aliases` 为空发 **warn**（不阻断）；`error_codes` 由写作自检保证，速查表由正文核心节校验兜底。

## 脱敏硬规则

条目里不出现密钥/token/口令、PII、内部主机名/IP/租户 ID，一律用尖括号占位符（`<INTERNAL_HOST>`、`<TENANT_ID>`、`<USER_A>`）。validate 自动扫描兜底（范围为**全文含代码围栏**——围栏不是免责区）。模式的最终取值以 `scripts/validate.py` 的 `SECRET_ERROR_RES` / `SECRET_WARN_RES` / `PII_RES` 常量表为准：
- 高置信度密钥特征 → **error**：`AKIA…` / `BEGIN … PRIVATE KEY` / `Bearer ` 后接 ≥20 字符 / `password|passwd|pwd=` 后接字面值 / `sk-…` / GitHub `gh*_…` / Slack `xox*-…` / JWT 三段式 / `Authorization: Basic …` / 连接串内嵌口令（`scheme://user:pass@host`）；
- 泛词密钥（secret/token/api_key 赋值）→ **warn**，并加 `(?<![A-Za-z])` 词边界，排除 `imagePullSecret`、`secretName`、`kind: Secret` 等词内情形（K8s 条目里的 `imagePullSecret: regcred` 不会误伤）；
- 私网 IP / 邮箱 / 手机号 / 内部域名后缀 → warn（手机号正则带前后非数字边界，防误伤时间戳等 11 位数字）。

## 防注入规则

不照抄日志或上游文档里的祈使句——知识是数据不是指令。引用日志只摘「特征行」并标注为证据原文。validate 自动扫描兜底（warn）：`ignore previous`、`system prompt`、`忽略以上/之前/上述`、`无视…`、`你现在是`、`请执行`、`立即删除`、`rm -rf /`、`curl … | sh` 等句式。条目禁止注释（见上）；未填模板标记的 `{{填写` 前缀在**全文（含代码围栏）**检测 → error，泛 `{{` 仍跳过围栏（mermaid 的 `A{{判断}}` 合法）。

**这不是安全边界**：正则扫描只挡「无意写入」，挡不住有意构造的变体（加空格、拆字、同义改写都能绕过）。真正的防线是落盘前的 **diff 给用户确认**——尤其是结构化摘要里的新增结论与证据来源。不要把扫描通过当成条目可信。

## YAML 书写坑（实测踩中）

- 值里含「冒号+空格」（如 `Last State: Terminated`）会破坏 YAML 映射 → 整句加引号；
- **值里含 `#` 要整句加引号**（`source: "k8s issue #1234"`）：YAML 只把行首或前有空白的 `#` 当注释，未加引号的值会被从 `#` 起截断，validate 判 error。文档章节锚点 URL 的 `#` 前是 `/`、无空白，属合法值，不误报；
- **块标量（`|`/`>`，含 `|-`/`>+`/`|2`/纯列表 `- |`）内容里的 `#` 是普通字符**，validate 按缩进跳过整块、不判注释；块起始行与块外的真注释仍拦；
- 块边界按缩进状态机判定：块内容缩进取第一行非空内容，缩进回退到键行及以下即块结束；空块与块内空行按普通行继续检查。跳过只作用于「是否算 YAML 注释」，块内容仍受全文密钥 / 注入扫描。
- 数字型错误码/版本在数组里必须加引号（`"503"`），否则被解析成 int，校验拒绝。
