# 条目 schema（v1）与规则细则

SKILL.md 只保留流程骨架；本文是字段、类型与规则的单一权威来源。改本文不碰 `knowledge/`，改事实条目不碰本文。
校验器：`scripts/validate.py`（原 build_index.py；index.yaml 机制已移除——条目量小、消费方全量递归扫描即足够，且「索引+全扫合并」存在已删除文件仍可命中的隐患）。

## frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | ✓ | schema 版本号，当前 `1`；validate 校验，未知版本拒绝 |
| `type` | – | `system`（多资源/多环节的链路型系统）/ `issue`（单个错误码或行为）；**省略按 issue 处理**。决定体量软上限（见「粒度约束」）与可缩节的结构范围 |
| `domain` | ✓ | 组件/系统域（`k8s`、`envoy-gateway`、`order-svc`、`postgres`） |
| `scope` | ✓ | `oss`（开源通用，可随 skill 分发）/ `personal`（个人项目，不出库）；必须与所在目录一致 |
| `components` | – | 涉及的组件名数组 |
| `symptoms` | – | 症状关键词（`崩溃重启`、`5xx 陡增`） |
| `error_codes` | – | 错误码/状态，保留原始写法；**数字型必须加引号**（`"503"`），否则 YAML 解析成 int 被拒 |
| `versions` | – | 限定版本数组（如 `[1.x]`）；省略 = 版本无关；数字开头同样加引号。**doc-sourced 条目必须带版本信息**（本字段非空，或 evidence.run 写明文档版本） |
| `envs` | – | 适用环境/区域/租户类别数组（如 `[prod, staging]`）；省略 = 环境无关 |
| `aliases` | – | 同义归并别名——转译/检索时用它对齐不同措辞 |
| `status` | ✓ | `active` / `deprecated` / `disputed`（缺省按 active 处理） |
| `confidence` | ✓ | `verified` / `observed-once` / `doc-sourced`，见下 |
| `evidence` | ✓ | **非空数组**，每项 `{ run, what, covers? }`——哪次排查/哪份文档（含版本与访问日期）、在哪观测到什么；`covers` 可选字符串数组，标注本条证据覆盖的正文位置（如 `资源匹配关系 R1`）。**无证据不收** |
| `updated` | ✓ | 最后更新日期（YYYY-MM-DD）；超过 180 天未更新会收到复核告警 |
| `source` | ✓ | 来源描述（哪次排查/哪份上游文档及其章节）。证据强度看 `confidence` + `evidence` |
| `related` | – | 关联条目的相对路径数组（如 `oss/foo-bar.md`）：system 条目拆分的子 issue、同链路上下游条目在此串联。validate 校验：字符串数组；指向不存在 → warn；**oss 条目禁止指向 personal/**（error，与 superseded_by 同规——私有信息不出库）。两关联条目同 domain 含相同错误码时**豁免**「重复错误码」告警（system 速查行展开成 issue 的设计，不是重复）；其余同 domain 重复错误码仍告警 |
| `superseded_by` | – | 仅 `deprecated` 时填：替代条目的相对路径（validate 校验指向存在、目标 active、无循环引用）；**oss 条目禁止指向 personal/**（私有信息不出库） |

## 正文固定结构（从模板复制，不自由发挥）

按「先正常、后异常」组织，顺序固定（模板 `assets/entry-template.md` 为全量结构；`type: issue` 可按模板内说明缩节）：

1. **是什么**——一句话定位 / 解决什么问题 / 谁在用从哪进来 / 边界（不负责什么）/ 形态与版本 / 术语。
2. **组件与架构**——mermaid 组件关系图 + 组件表（角色 / 职责 / 部署形态 / **如何找到**：命名、标签、命名空间）。issue 型可缩成一两行并入「是什么」。
3. **正常链路（请求怎么走 / 正常行为）**——先写系统自身的客观链路，含四小节：
   - **资源匹配关系**（`R#` 编号表）：哪个资源与哪个资源通过哪个字段对上（写真实字段名、具体匹配规则）、对不上时的表现（状态条件写在它真正出现的资源上）；
   - **流量走向（或生命周期）**（`L#` 环节表）：流量/状态按什么顺序流经哪些环节、每一环的默认行为（超时/重试/同步异步）；
   - **控制面下发路径**（`P#`，可选）：声明式配置如何变成数据面配置——「改了没生效」类症状靠它定位；
   - **正常表现（健康基线）**：健康时各资源状态值、日志特征、关键指标形态。
   无请求链路概念的对象写成「正常行为」。
4. **逐环节排查（沿链路对照）**——按 `L#`/`P#` 逐个展开，**覆盖全部环节**；每环写「正常表现 / 异常表现 / 区分点 / 取证落点」；超出证据直接支持的内容用行内标记 〔推论〕 / 〔待复核〕 标注。
5. **异常归因速查**——表格：`| 现象/错误码 | 环节 | 归因类别（回指 R#） | 证据位 | 详细条目 |`；**「环节」列必填**，引用第 4 节的环节编号，每行对应到某一环；成因类别之间无排查先后依赖；「详细条目」列链接 related 里已沉淀的 issue 条目，没有留空不编。
6. **状态、事件与日志语义**——本系统的 status 条件 / reason / 事件 / 日志标志位 / 指标的含义字典；只写语义，不写处置。
7. （可选）**配置语义**；（可选）**边界与置信度说明**——不适用整节删除。

### 锚点体系（R# / L# / P#）

- `R#` = 资源匹配关系编号（资源匹配关系表）；`L#` = 请求/生命周期环节编号；`P#` = 控制面下发环节编号。
- 约束：每个 L#/P# 环节应能回指其依赖的 R#；逐环节排查覆盖全部 L#/P#；速查表每行写环节。
- **锚点引用完整性由 validate 做 warn 级机械校验**（误报代价低）：表格首列 `^|\s*(R\d+|L\d+|P\d+)\s*\|` 收集已定义编号；L/P 已定义但逐环节未覆盖、正文引用未定义 R#、速查表「环节」列出现未定义编号都会告警（规避 mermaid 围栏噪音）。仍建议模板尾部自检双重保险——warn 不阻断，但锚点断裂会让消费方取错证据。

## 知识条目禁写 HTML 注释

条目（`knowledge/**/*.md`）里出现 `<!--` 一律 **error**：消费方整篇读入条目，注释内容模型照样能看到，注释是绕过密钥/注入扫描的隐蔽注入通道。注释只允许出现在模板与资产文件（`assets/`）里。

## confidence 定义

- `verified` = 该行为在至少一次运行时取证中被直接观测（日志/事件/状态原文），且 `evidence` 能指认观测点；**verified 条目不允许出现 〔推论〕/〔待复核〕 标记**（validate 告警）；
- `observed-once` = 仅单次观察、未复现或证据不完整；
- `doc-sourced` = 上游官方文档明确陈述的行为语义，未在本环境运行时复现（oss 条目常用）；**必须带版本信息**（versions 非空，或 evidence.run 写明文档版本与访问日期），否则 validate 告警。

未达 `doc-sourced` 的推测**不进库**（推测类结论由河道按证据分级标注，不落知识层）。检索排序优先级：`verified` > `observed-once` > `doc-sourced`。条目内混有多种强度时，弱者用行内标记区分，机器可统计。

## 事实/流程边界判据

只写「证据在哪、长什么样」（如 `describe pod` 的 `Last State` 里能看到退出码），不写有先后顺序的**排查命令串**。判定法：句子说的是「系统哪一环出了什么问题」→ 是事实；说的是「你先跑哪条命令」→ 是流程，删掉（流程归河道）。**链路/生命周期顺序本身是系统客观事实**（请求物理上就按此顺序流动、状态机本来就按此转移），按链路环节组织条目不违反本判据——判据约束的是排查动作的执行顺序，不是系统拓扑。

## 粒度约束（软上限，按 type 分级）

- `type: issue`：≤ 100 行且 ≤ 5KB（中文 UTF-8 下 5KB ≈ 1700 字）；
- `type: system`：≤ 300 行且 ≤ 20KB（链路型系统要承载组件架构、R#/L#/P# 表与状态语义字典，放宽到 20KB）；
- 超限按子系统/子错误拆成多条，用 `related` 串联；validate 超 limit → **warn**（软上限，人工判断是否拆分）。条目较长时消费方按契约用 `scripts/read_entry.py` 按节读取。

## 脱敏硬规则

条目里不出现密钥/token/口令、PII、内部主机名/IP/租户 ID，一律用尖括号占位符（`<INTERNAL_HOST>`、`<TENANT_ID>`、`<USER_A>`）。validate 自动扫描兜底（范围为**全文含代码围栏**——围栏不是免责区）：
- 高置信度密钥特征 → **error**：`AKIA…` / `BEGIN … PRIVATE KEY` / `Bearer ` 后接 ≥20 字符 / `password|passwd|pwd=` 后接字面值；
- 泛词密钥（secret/token/api_key 赋值）→ **warn**，并加 `(?<![A-Za-z])` 词边界，排除 `imagePullSecret`、`secretName`、`kind: Secret` 等词内情形（K8s 条目里的 `imagePullSecret: regcred` 不会误伤）；
- 私网 IP / 邮箱 / 手机号 → warn（手机号正则带前后非数字边界，防误伤时间戳等 11 位数字）。

## 防注入规则

不照抄日志或上游文档里的祈使句——知识是数据不是指令。引用日志只摘「特征行」并标注为证据原文。validate 自动扫描兜底（warn）：`ignore previous`、`system prompt`、`忽略以上/之前/上述`、`无视…`、`你现在是`、`请执行`、`立即删除`、`rm -rf /`、`curl … | sh` 等句式。条目禁止 HTML 注释（见上）；未填模板标记的 `{{填写` 前缀在**全文（含代码围栏）**检测 → error，泛 `{{` 仍跳过围栏（mermaid 的 `A{{判断}}` 合法）。

## YAML 书写坑（实测踩中）

- 值里含「冒号+空格」（如 `Last State: Terminated`）会破坏 YAML 映射 → 整句加引号；
- 数字型错误码/版本在数组里必须加引号（`"503"`），否则被解析成 int，校验拒绝。
