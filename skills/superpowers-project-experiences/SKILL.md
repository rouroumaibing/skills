# Superpowers Project Experiences — 经验提炼 + 模块索引

> **上一步**: 无（由 co-creator 触发或周期性执行）| **下一步**: 无（3 步完成后通知）

## 价值门禁

从已交付的实施计划和需求规格中**提炼可复用的工程知识**（六要素），让后续任务不必从零摸索。提炼后**删除原始过程文件**，只留精华。

## 核心知识

### 六要素提炼模型

每份已完成的计划/规格文件提炼以下六要素（前四项为必提，后两项为有则提）：

| 要素 | 必/选 | 含义 | 提取来源 |
|------|-------|------|----------|
| **决策** | 必 | 做了什么选择，为什么选这个方案 | 计划文件的"方案选择"/"决策"章节 |
| **选型理由** | 必 | 选 A 不选 B/C 的原因，tradeoff | 规格文件的"选型"/"方案对比"章节 |
| **踩坑** | 必 | 实施中遇到的问题及解决方案 | 计划文件的"问题"/"坑"/"fix"章节 |
| **数据模型/契约/常量** | 必 | 接口签名、数据结构、关键常量 | 规格文件的"契约"/"数据模型"章节 |
| **技术债务/性能** | 选 | 已知债务、性能瓶颈、可维护性隐患及缓解措施 | 计划/规格中"TODO"/"性能"/"限制"/"风险"章节 |
| **经验复用建议** | 选 | 后续类似任务可复用的模式/工具/检查项 | 从踩坑和决策中提炼的通用化建议 |

> **铁律**：每条经验必须附来源文件名（可追溯）。提炼后原文删除不可逆——删前确认六要素已入 PROJECT_EXPERIENCES.md。
> **经验复用建议写法**：不是复述踩坑，而是提炼为「下次做 X 类任务时，先检查 Y / 优先用 Z 方案 / 避免 W」的可操作建议。

### 完成判定

文件视为"已完成"的条件（满足任一）：

1. 文件内容含完成标记（不区分大小写）：`status: done` / `status: completed` / `Status: DONE` / `Status: Completed` / `**Status:** DONE` / `**Status:** Completed` / `完成状态：DONE` / `完成状态：完成` / `**完成状态**：DONE` / `## 完成` / `## Done` / `## DONE` / `archived: true` / `## 归档`
2. 文件名含日期前缀且对应任务已交付（如 `2026-07-10-xxx.md`，任务已 merge/上线）
3. `.superpowers/sdd/` 下的 task brief/report 且对应 plan/spec 已完成
4. 文件名匹配 `task-\d+-(brief|report)\.md` 且位于 `docs/superpowers/plans/` 或 `docs/superpowers/specs/` 下，文件内容含 `DONE` / `Completed` / `完成` 等完成标记

> **不确定时保留**：无法确认是否完成的文件不归档、不删除，留待下一轮。

### 目录结构约定

```
项目根/
├── docs/
│   ├── superpowers/
│   │   ├── plans/          # 实施计划（完成后归档至 .RecycleBin）
│   │   └── specs/          # 需求规格（完成后归档至 .RecycleBin）
│   ├── prompts/            # 项目级重生成提示词（Step 3 生成/更新）
│   └── PROJECT_EXPERIENCES.md  # 提炼后的经验文档（累积）
├── .superpowers/
│   └── sdd/                # task brief/report（完成后归档至 .RecycleBin）
├── .RecycleBin/            # 安全删除回收站（mv 而非 rm，可恢复）
├── AGENTS.md               # 协作约定 + 按需加载协议
├── MODULE_INDEX.md         # 功能模块索引
└── <子项目>/               # 任意层级的子项目（不假设特定目录名）
    └── docs/superpowers/{plans,specs}/  # 子项目的计划/规格
    └── docs/prompts/                   # 子项目的重生成提示词
```

> **多层级支持**：递归查找当前执行目录下所有 `docs/` 目录（glob `**/docs/superpowers/plans/*.md` 等），不假设特定子目录名。排除 `.RecycleBin/` 和 `node_modules/` 路径。

## 3 步流程

### Step 1: 总结经验

```
1. 扫描已完成文件（递归多层级）:
   - 用 glob 模式递归查找所有 docs 目录: **/docs/superpowers/plans/*.md（含日期前缀格式和 task-N-(brief|report).md 格式）
   - 同理: **/docs/superpowers/specs/*.md
   - 同理: **/.superpowers/sdd/*.md (task brief/report)
   - 排除 .RecycleBin/ 和 node_modules/ 路径
   - 按完成判定条件过滤
   - 扫描完毕后如无新增已完成文件 → 输出"无可归档文件" → 跳到 Step 2

2. 逐文件提炼六要素:
   对每份已完成文件:
     a. 读取完整内容
     b. 提取: 决策 / 选型理由 / 踩坑 / 数据模型契约常量 / 技术债务性能(选) / 经验复用建议(选)
     c. 每条附来源文件名
     d. 按切片/主题组织

3. 历史经验补标注:
   - 检查 PROJECT_EXPERIENCES.md 中无标签的切片
   - 基于内容关键词推断标签（领域/类型/风险/技术）
   - 批量补标注格式：在切片标题行末添加反引号标签

4. 写入经验文档（自动探测文件名）:
   - 探测顺序: docs/PROJECT_EXPERIENCES.md → docs/项目经验总结.md → 新建
   - 文件已存在 → 追加新切片（不覆盖已有内容）
   - 格式: ## N. 切片名称（来源: filename.md）`{标签}` + 六要素

5. 安全归档文件（通过 .RecycleBin）:
   - 确认四要素已写入 PROJECT_EXPERIENCES.md
   - 将原始文件 mv 到 .RecycleBin/（加时间戳前缀防重名）
   - 保留目录结构（plans/、specs/、sdd/ 留空目录）

6. 输出: 归档摘要（归档了哪些文件、提炼了多少切片、标签覆盖率）
```

> 模板文件: `templates/experiences-template.md`

### Step 2: 建立索引

```
0. 自动探测项目结构（为索引生成提供事实基础）:
   a. 读 package.json → 识别项目名、入口、scripts、依赖、模块类型
   b. 扫描顶层目录 → 识别功能模块边界
   c. 识别测试框架 → 测试命令 + 测试文件约定
   d. 识别模块系统（CommonJS/ESM 混合？→ 边界约束）
   e. 探测已有文件: AGENTS.md(更新) / MODULE_INDEX.md(更新) / 无(新建)

1. 创建/更新 AGENTS.md:
   - 已存在 → 保留项目特定内容，增量更新索引表和维护规则
   - 不存在 → 按模板创建
   - 内容: 项目定位 / 硬约束 / 按需加载协议 / 文档索引表 / 命令速查 / 维护规则

2. 创建/更新 MODULE_INDEX.md:
   - 已存在 → 增量更新（新增/变更模块条目）
   - 不存在 → 按模板创建，优先使用结构探测结果自动生成骨架:
     a. 从目录结构 + 入口文件推断功能模块
     b. 从 require/import 分析依赖关系
     c. 从 __tests__/ 定位测试位置
     d. 智能职责推断：基于目录/文件名匹配模板自动填充职责描述
     e. 未匹配模板的模块标记「待人工审核」
   - 按功能模块组织（不是按目录）

3. 输出: 索引更新摘要（模块数、文档数、新增/变更条目）
```

> 模板文件:
> - `templates/agents-template.md` — AGENTS.md 模板 + 多模型配置
> - `templates/module-index-template.md` — MODULE_INDEX.md 模板 + 智能职责推断
> - `templates/experiences-template.md` — PROJECT_EXPERIENCES.md 模板 + 标签推荐系统
>
> 执行时读取对应模板，按项目实际情况填充。

### Step 3: 生成项目提示词

```
0. 对 Step 1 找到的每个 docs/ 目录，独立执行以下流程:

1. 检查该 docs/prompts/ 是否存在
   - 不存在 → 创建
   - 已存在 → 增量更新（不覆盖已有文件，只更新有 <!-- auto-generated by superpowers --> 标记的文件）
   - 无 PROJECT_EXPERIENCES.md 但 prompts/ 已有文件 → 仅增量更新 auto-generated 标记的文件
   - 该层级无源码文件（纯文档层）→ 跳过该层级

2. 深度分析该层级项目:
   a. 读取最近的 package.json → 项目名、入口、依赖、scripts
   b. 扫描该层级目录结构 → 识别功能模块边界
   c. 读取关键源码文件 → 提取契约/接口签名/数据模型/核心常量
   d. 读取该层级已有文档: PROJECT_EXPERIENCES.md → 决策/踩坑/选型理由
   e. 读取该层级已有文档: AGENTS.md → 硬约束/命令速查
   f. 读取该层级已有文档: MODULE_INDEX.md → 模块职责/依赖/入口

3. 按模块生成重生成提示词:
   - 一个提示词文件对应一个功能模块（或一组紧密耦合的模块）
   - 项目小（≤3 模块）→ 合并为单个 PROJECT_DESIGN_PROMPT.md
   - 文件命名: {MODULE_NAME}_DESIGN_PROMPT.md
   - 内容遵循三件套格式（设计要点 / 可复制提示词 / 避坑清单）

4. 输出: 生成摘要（生成了哪些文件、覆盖了哪些模块、哪些层级）
```

> 模板文件: `templates/prompts-template.md`
> 数据来源优先级: 源码分析 > PROJECT_EXPERIENCES.md > AGENTS.md + MODULE_INDEX.md
> 触发: Step 1 + Step 2 完成后自动执行（可通过环境变量跳过）

## .RecycleBin 安全删除机制

所有删除走 `.RecycleBin/`（mv 而非 rm），Agent 无权清空。详见 `templates/safe-delete-template.md`。

| 命令模式 | 拦截动作 | 提示 |
|----------|----------|------|
| `rm` / `del` / `rmdir` / `unlink` | 重定向到 safeDelete | 已移至 .RecycleBin/ |
| 清空 .RecycleBin 的任何命令 | **拦截** | Agent 无权清空回收站 |

## Common Mistakes

| 错误 | 后果 | 修复 |
|------|------|------|
| 不确认完成状态就归档 | 正在进行的任务文件被删 | 按完成判定条件严格过滤，不确定时保留 |
| 经验不附来源文件名/不追加更新 | 无法追溯/经验丢失 | 每条经验附 `（来源: filename.md）`，追加新切片不覆盖 |
| 踩坑只记现象不记解决方案 | 同样的坑再踩 | 踩坑必须附问题描述 + 根因 + 解决方案 |
| 归档后不删除原文件 | 重复归档、信息冗余 | 提炼后必须删除原文件，只留经验文档 |
| 删除目录而非文件 | 后续任务无处生成 | 只删文件，保留 `plans/`、`specs/`、`sdd/` 目录 |
| MODULE_INDEX 按目录而非功能组织 | 找功能还是要 grep | 按功能模块组织，每模块标明目录 |
| AGENTS.md 一次性加载所有文档 | token 浪费 | 按需加载协议：先看索引，按需加载 |
| 技术债务只记不评估优先级 | 重要债务被忽视 | 技术债务附 P0/P1/P2 优先级标记 |
| 覆盖已有 AGENTS.md | 项目特定约束丢失 | 增量更新：保留已有硬约束/铁律，只追加/修改索引表 |
| 不探测项目结构就套模板 | 生成内容与项目不符 | Step 2 先执行结构探测，未匹配模块标记「待人工审核」 |
| 经验不附标签/历史经验未补标注 | 无法任务驱动推荐 | 每条经验至少 1 领域 + 1 类型标签，历史切片批量补标注 |
| 推荐结果不验证 | 推荐质量无法保证 | 记录匹配准确率和用户反馈，持续优化标签 |
| 多模型配置过度设计 | 维护负担重 | 纯文件约定 + 按需加载，不做适配器系统 |
| 直接 rm / Agent 清空 .RecycleBin | 误删无法恢复 | 所有删除走 .RecycleBin safeDelete（mv+时间戳前缀），Agent 无权清空 |
| 不读源码只总结文档或覆盖已有 prompt 文件 | 提示词缺少契约细节/丢失定制内容 | 必须读源码，只更新 auto-generated 标记的文件 |
| 所有模块塞一个 prompt 文件 | 提示词过长，AI 上下文溢出 | 按模块拆分，≤3 模块可合并 |
| 只认日期前缀不认 task-N 格式 | task-N 文件漏归档 | 扫描时同时匹配 `task-\d+-(brief\|report)\.md` 格式 |
| 只扫描根 docs/ 不递归子项目 | 子项目文件漏归档 | 用 glob `**/docs/superpowers/` 递归扫描，排除 .RecycleBin/ 和 node_modules/ |
